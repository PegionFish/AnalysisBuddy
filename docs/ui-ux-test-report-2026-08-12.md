## 3. Findings

### P1 — 卸载插件是不可逆操作，却没有确认、撤销或完成反馈

#### 用户影响

用户在插件管理页误点“Uninstall / 卸载”后，插件会立即从列表中消失。该行为是破坏性操作：用户可能失去已配置的第三方插件，且无法在界面中确认“是否真的要删除”、取消操作，或在删除后立即恢复。

#### 复现步骤

1. 打开 `Plugins / 插件`。
2. 选择非内置插件 `demo-tool`。
3. 点击 `Uninstall / 卸载`。
4. 观察插件列表。

#### 实际结果

- 没有浏览器或应用内确认对话框。
- 没有提示条、Toast、撤销入口或回收机制。
- 插件条目立即从列表中移除。

#### 期望结果

至少提供以下其中一种安全机制，推荐组合使用：

1. 卸载前的确认对话框，明确显示插件名称与风险；
2. 卸载成功后的短暂 Toast，并提供“撤销”；
3. 如插件包含用户数据或配置，应明确说明删除范围；
4. 卸载期间禁用重复点击，成功后聚焦到下一条插件或插件页标题，避免键盘/读屏用户失去上下文。

#### 源码定位

- 卸载事件直接执行：[PluginManagerPage.tsx](../ui/src/components/PluginManagerPage.tsx#L202)
- 卸载按钮触发点：[PluginManagerPage.tsx](../ui/src/components/PluginManagerPage.tsx#L418)
- 状态层在 IPC 成功后直接移除条目：[session.ts](../ui/src/state/session.ts#L540)

#### 修复建议

新增带焦点管理的确认 Dialog，例如：

> 确定卸载 “Demo Tool” 吗？  
> 此操作将移除该插件。若插件含有本地配置，请确认是否保留或一并删除。  
> `[取消] [卸载插件]`

完成后显示：

> 已卸载 Demo Tool。`[撤销]`

### P2 — 390px 窄屏下布局宽度超过视口两倍，主要工作区被挤出屏幕

#### 用户影响

在 390 × 844 的窄屏测试中，页面实际内容宽度为 **792px**，导致明显的横向滚动。左侧文件面板占据可见区域，中央图表区和右侧关键值区被挤到屏幕外；顶部部分操作也无法完整显示。

这使小尺寸窗口、分屏、触控设备、远程桌面或高缩放比例下的用户，必须反复横向滚动才能完成工作。

#### 复现步骤

1. 打开工作台。
2. 将窗口或浏览器视口缩窄到 390px。
3. 观察顶部工具栏与三栏工作区。

#### 实际结果

- 文档存在水平溢出：`scrollWidth = 792`，`viewportWidth = 390`。
- 出现横向滚动条。
- 中央空状态只剩局部文字，右侧“关键值”面板不可见。
- 文件路径输入框在窄屏下发生文本裁切，按钮排列也缺乏优先级重排。

#### 修复建议

采用渐进式响应策略，而不是强制压缩三栏：

| 断点 | 推荐布局 |
|---|---|
| ≥ 1200px | 左侧文件/指标 + 中央图表 + 右侧关键值三栏 |
| 800–1199px | 左侧可折叠；右侧关键值收为抽屉或图表下方区域 |
| < 800px | 单列：文件/指标 → 图表 → 关键值；顶部操作栏折叠为溢出菜单 |

同时建议为图表区域设置合理的 `min-width: 0`，并将关键值面板改为可折叠面板，避免整个页面由固定栏宽决定最小宽度。

### P2 — 文件拖拽区没有键盘可访问的等价入口

#### 用户影响

工作台和插件页均以拖拽区作为主要导入暗示；但日志文件拖拽区在 DOM 中是普通 `<div>`，没有 `role`、`aria-label`、键盘焦点或“选择文件”按钮。对于键盘用户、读屏用户、触控用户、无法拖放文件的远程桌面用户，导入入口不够直观，也不具备等价操作方式。

虽然文件面板提供了“输入文件路径”的文本框作为替代，但它需要用户先知道完整路径，且缺少明确的浏览文件入口。

#### 复现证据

测试中拖拽区的结构为：

```html
<div class="file-panel__dropzone" data-testid="dropzone">
  <span>Drag log files here</span>
</div>
```

其语义检查结果：

- `role = null`
- `aria-label = null`
- `tabIndex = -1`

#### 源码定位

- [FilePanel.tsx](../ui/src/components/FilePanel.tsx#L239)
- [FilePanel.css](../ui/src/components/FilePanel.css#L15)

#### 修复建议

- 在区域内放置明确的主按钮：`选择日志文件…`；
- 让整个区域支持 `Enter` / `Space` 打开文件选择器；
- 添加 `role="button"`、可见焦点样式、`aria-label` 或关联说明；
- 说明支持的格式、是否允许多选、导入后的下一步；
- 不把“拖拽”作为唯一或主要操作方式。

建议文案：

> 拖放日志文件到此处，或 `[选择文件]`  
> 支持 CSV、……；可一次导入多个文件。

### P2 — 多个主要操作控件过小，文字与点击目标不利于高缩放、触控和可访问性

#### 用户影响

实测中部分关键控件为 12px 字号，视觉高度约 24–26px，例如：

- 工作台 / 插件导航按钮：约 24px 高；
- 主题按钮：约 26px 高；
- 文件导入输入框与导入按钮：约 26px 高；
- 插件管理页的 Disable / Reload / Logs 等操作按钮也较紧凑。

在高 DPI、小尺寸窗口、触控屏或手部动作不稳定时，容易误点；较小的文字和低对比边框也会增加阅读负担。

#### 建议标准

- 触控/主要操作目标：建议不低于 40–44px。
- 常规桌面辅助操作：建议至少 32px。
- 默认正文和主要控件文字：建议至少 14px，避免 12px 作为常规交互文本。
- 连续的小按钮组应增加间距或改为菜单，避免误触。

#### 修复建议

- 将顶部操作栏中的主要操作调整为 32–36px 高；
- 将“保存会话 / 另存为 / 新建会话”区分主次，减少所有动作等权、拥挤排列；
- 将插件卡片的次级操作收进 `更多` 菜单，保留“启用/禁用”作为直接操作；
- 为键盘焦点提供更明显且全局一致的焦点环。

## 4. 体验亮点

- **信息架构直观：** 工作台围绕“文件 → 指标 → 图表 → 关键值”组织，符合日志分析任务的自然流程。
- **空状态清晰：** 首次进入时明确显示“开始分析”，并告诉用户“导入文件并勾选指标后，曲线将显示在这里”。
- **双语切换即时生效：** 中文和英文文本随语言选择同步切换，未见残留语言。
- **主题切换即时生效：** 界面状态和主题按钮文案随切换正确变化。
- **插件状态可理解：** `Ready / Disabled` 状态与 `Enable / Disable` 动作匹配，插件卡片信息层次清楚。
- **内置插件保护可见：** 内置 `builtin-csv` 不显示卸载按钮，降低了误删系统插件的风险。
- **前端稳定性良好：** 整个已测流程未出现框架错误覆盖层或控制台告警。

## 5. 建议的修复优先级

| 优先级 | 建议 | 价值 |
|---:|---|---|
| P1 | 插件卸载增加确认、撤销与完成反馈 | 避免不可逆误操作 |
| P2 | 三栏工作台增加窄窗口/高缩放的自适应布局 | 修复关键使用场景的横向溢出 |
| P2 | 拖拽区补充“选择文件”及键盘/读屏语义 | 提升导入流程可达性 |
| P2 | 提升控件最小尺寸、字号和间距 | 改善触达性、可读性与误触风险 |
| P3 | 优化顶部操作栏的主次层级 | 减少首次使用的认知负担 |
| P3 | 为导入、保存、插件操作补充统一 Toast/状态反馈 | 提升操作结果的可感知性 |

## 6. 覆盖边界与剩余风险

本次报告基于实际渲染界面和可交互 mock 状态得出，不是静态代码审查。以下路径未在本轮完成端到端验证：

- 真实 Tauri 桌面 IPC 下的文件选择、导入、会话保存/打开；
- 使用真实日志数据后的指标树、曲线渲染、图表缩放、游标和“关键值”联动；
- 导入失败、格式不支持、解析部分失败、重复文件、缺失文件等错误状态；
- 插件 ZIP 上传、冲突处理、日志查看与插件重载失败状态；
- Windows 高 DPI（125%、150%、200%）与小窗口的真实桌面壳表现；
- 屏幕阅读器实际朗读体验及完整键盘焦点顺序。

## 7. 最终建议

AnalysisBuddy 已具备可理解的桌面工作台骨架。下一阶段最值得投入的是“安全的破坏性操作”“窄窗口适配”与“非拖拽导入入口”，这三项能明显提升真实用户的信心和完成任务的效率。
